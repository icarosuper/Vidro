# Architecture

Read this doc before creating routes, new features or cross-cutting changes (api-client, shared types, root providers).

## Stack

- **Framework:** TanStack Start (selective SSR, file-based routing)
- **Data fetching:** TanStack Query
- **UI:** shadcn/ui + Tailwind CSS v4
- **Forms:** in-house components + inline validation (no react-hook-form)
- **Notifications:** sonner (`toastApiError` centralizes API errors)
- **Package manager:** bun
- **Lint/format:** Biome
- **Tests:** Vitest

## Layers and responsibilities

| Layer | Role | Imports from |
|---|---|---|
| `routes/*` | File-based routing, loaders, `beforeLoad` (auth guard), composing feature components | `features/*`, `shared/*`, `components/*` |
| `features/*/api.ts` | Typed functions → `apiClient`. Never direct `fetch` (except presigned uploads) | `shared/lib/api-client`, `./types` |
| `features/*/hooks.ts(x)` | TanStack Query hooks (`useQuery`/`useMutation`/`useInfiniteQuery`) + invalidations | `./api`, `shared/lib/toast-error` |
| `features/*/server.ts` | Server functions (`createServerFn`) for SSR or operations that need the httpOnly cookie | `@tanstack/react-start`, `./types` |
| `features/*/components/*` | Feature-specific UI | Any layer below |
| `shared/lib/api-client.ts` | The single HTTP entry point: injects the token, unwraps `{ data: T }`, retries on 401 | `shared/types`, `token-store` |

## API client rule

**No feature calls `fetch` directly.** All HTTP goes through `apiClient` (`src/shared/lib/api-client.ts`). Exceptions:

- **Uploads via presigned URL** (MinIO/S3): direct `fetch` PUT to the URL — the credential is in the URL itself, do not send `Authorization`.
- **Server functions** (`features/*/server.ts`): they run on the server, with no access to `tokenStore`; direct `fetch` with the token passed as an argument.

Pattern:

```ts
// features/videos/api.ts
export function getVideo(videoId: string, signal?: AbortSignal) {
  return apiClient.get<Video>(`/v1/videos/${videoId}`, signal)
}

// features/videos/hooks.ts
export function useVideo(videoId: string) {
  return useQuery({
    queryKey: ['videos', videoId],
    queryFn: ({ signal }) => getVideo(videoId, signal),
  })
}
```

### `apiClient` responsibilities

- Adds `Authorization: Bearer <token>` automatically when there is a token in `tokenStore`
- Adds `X-Correlation-ID` (one per request, from `shared/lib/correlation-id.ts`)
- Serializes the JSON body; handles `204 No Content`
- On **401**: calls `renewTokenCallback` (configured in `__root.tsx`), sets the new token, retries **once**. If the retry fails, clears the token and throws `ApiClientError`
- On error, throws `ApiClientError { code, message, status, correlationId }` — always use `toastApiError`
- Deserializes the `{ data: T }` envelope, returns `T`

### Correlation ID

Every outgoing call carries `X-Correlation-ID`, generated in `shared/lib/correlation-id.ts`. The API
accepts the incoming header (`CorrelationIdMiddleware`), returns it in the response and stamps the
value on **every log line of that request** — so the id the front generates is the one to search
for in Loki.

- `ApiClientError.correlationId` holds the id of the request that failed.
- `RouteErrorFallback` shows that id ("Reference for support") for the user to quote. It reads the
  property by shape, **not** by `instanceof`: an error thrown in an SSR loader reaches the
  browser serialized, without the class.
- **The exceptions to the "no direct `fetch`" rule also send the header** — both
  `features/*/server.ts` files call `newCorrelationId()` by hand. The presigned upload is the only
  outgoing call without it, on purpose: it goes to MinIO, not to the API, and the signed URL does
  not tolerate an extra header.
- `crypto.randomUUID` is `undefined` in a browser outside a secure context (http on a host that is
  not localhost); hence the fallback — it is a correlation id, not a security token.

### Generated API types

The front does not hand-write the API's request/response shapes. They flow from a single source:

1. The C# request/response records in `VidroApi` (the source of truth)
2. → `VidroApi/openapi/v1.json` (generated and committed on the API side — see `VidroApi/openapi/README.md`)
3. → `src/shared/api/schema.d.ts` (generated by `bun run openapi`; committed; ignored by Biome; never edit)
4. → named aliases in `src/shared/api/types.ts` over `components['schemas'][...]` (e.g. `Video = Schemas['GetVideoResponse']`)
5. → each feature's `types.ts`, which is just an `export type { ... } from '#/shared/api'` barrel

- **The runtime did not change:** `apiClient` still unwraps `{ data: T }`, and call sites pass the
  unwrapped alias as `T` (`apiClient.get<Video>(...)`). The aliases describe the `data`, not the
  envelope.
- **Success bodies only.** Error bodies (`ApiError`, `ValidationError`) remain hand-written in
  `shared/types.ts`.
- **Changing an API record** means regenerating `v1.json` and then running `bun run openapi`, in the
  same commit. Otherwise CI is red: `.github/workflows/front.yml` regenerates `schema.d.ts` and fails
  on any diff (and `api.yml` does the same for `v1.json`).

### Enums mirrored from the backend

`shared/types.ts` retypes six API enums (`VideoStatus`, `VideoVisibility`, `ReactionType`,
`PlaylistVisibility`, `PlaylistScope`, `CommentSortOrder`) because the API serializes them as
**integers**. Do not invent a new value and do not change a number here: the contract is
[`contracts/enums.json`](../../../contracts/README.md) at the monorepo root, and
`src/tests/enum-contract.test.ts` fails if this file diverges from it — as does the test on the
API side. Changing a member means changing the golden and both sides in the same commit.

The enums' numeric ids now also appear in the generated request types (e.g. `visibility: 0 | 1 | 2`),
but the generated schema carries only the numbers — the **names** (`Public`, `Unlisted`, ...) still
live only in `shared/types.ts`, pinned by `contracts/enums.json`.

## Rendering strategy

| Route | Strategy | Notes |
|---|---|---|
| `/` | SSR | Loader prefetches trending |
| `/watch/$videoId` | SSR | Loader uses `fetchVideoSsr` with the `accessToken` from the context |
| `/search` | SSR | Query in `?q=` (`validateSearch`); no prefetch in the loader |
| `/$username`, `/$username/$channel` | SSR | (ISR in the future) |
| `/upload`, `/dashboard`, `/settings` | Client-only | `beforeLoad` redirects to `/` if not authenticated |

`__root.tsx` resolves the initial token on the server via `getInitialToken()` and passes it through the router context → authenticated SSR routes without a waterfall.

### Error and not-found fallback

`src/router.tsx` registers `defaultErrorComponent` and `defaultNotFoundComponent`
(`components/RouteFallback.tsx`), so **every** route inherits both — an invalid URL, `notFound()`
or a throw in a loader/render lands on a screen with a way back instead of a blank screen. A route
only declares its own when it can do better.

That covers **route** errors. **Query** errors are still the component's job: handle the `useQuery`
`isError` in the screen itself (the repo pattern is a centered `text-muted-foreground` paragraph),
because the router fallback does not see a query that failed after the route has already rendered.

## SEO and per-route `head`

Every route declares its `head` with the `seo()` helper (`src/shared/lib/seo.ts`), which builds the
title, description, Open Graph and Twitter card in one go. `__root.tsx` provides the default, and a
route that declares nothing inherits it.

- **Title:** `seo()` appends `· Vidro` — pass only the page's part (`'Dashboard'`), never the
  full title. `'Vidro'` is the only one that gets no suffix.
- **Private or search-result pages** pass `noIndex: true`.
- **Routes with dynamic data** (watch, playlist) read from `loaderData`, and the loader returns what
  it took from the cache with `queryClient.getQueryData` — **not** the result of `ensureQueryData`.
  `prefetchQuery` swallows the error; switching to a query that throws would turn a broken meta tag
  into a broken page.
- **`og:url` is not emitted**: there is no public URL configured in the project, and the crawler
  falls back to the URL it fetched itself. Once there is a domain, this is where it goes.
- **The watch page's `og:image` is a presigned MinIO URL** and therefore expires — a card cached
  for too long loses the image. Really fixing it requires a public artifact or a proxy URL.

The UI language is **English** (`<html lang="en">`); dates use `toLocaleDateString('en-US')`.

## API response formats

The success shapes come from the generated schema (`src/shared/api/schema.d.ts`, aliased in
`src/shared/api/types.ts`); the error shapes are hand-written in `src/shared/types.ts`:

```ts
// Success: always { data: T } — apiClient unwraps it to T; the aliases describe T
// Error: { code: string; message: string } (ApiError), or ValidationError for FluentValidation 400s
// Enums in responses: { id: number; value: string } (EnumValue, from #/shared/api). In requests, send only the id.
// Videos/comments pagination: { [key]: T[], nextCursor: string | null } — e.g. FeedPage, CommentsPage
// Playlists pagination: { items: T[], nextCursor: string | null } — PlaylistsPage
// Deleted comments: kept in the UI with isDeleted: true, content: null
```

Enums mirrored from the backend: `VideoStatus`, `VideoVisibility`, `ReactionType`, `PlaylistVisibility`, `PlaylistScope`, `CommentSortOrder`.

Error codes are in `API_ERROR_CODES` — use them when mapping user-facing messages in `shared/lib/error-messages.ts`.

## Query key convention

Format: `['resource-type', id, ...sub]`. Examples:

```ts
['videos', videoId]
['videos', 'trending']
['videos', 'feed']
['channels', handle]
['users', 'me']
['channels', channelId, 'videos']
```

A module may export `*Keys` to centralize them (see `features/users/hooks.ts`: `userKeys.me()`).
